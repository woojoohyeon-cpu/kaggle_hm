# 브리핑: H&M Kaggle 추천 시스템 프로젝트 — 13장 차트 설명 요청

아래는 Kaggle "H&M Personalized Fashion Recommendations" 경진대회(평가지표: MAP@12, 고객별
추천 상품 12개의 순위 정확도) 프로젝트를 진도보고용 PPT로 만들기 위해 그린 차트 13장이다.
차트 안의 텍스트는 전부 일본어다. 각 이미지 파일명과 순서, 어떤 내용을 담고 있는지는 아래와 같다.
이 브리핑을 참고해서 각 차트가 무엇을 보여주는지, 그리고 전체 스토리가 어떻게 이어지는지
PPT 대본/설명으로 풀어써 줘.

## 프로젝트 개요

- 목표: 고객별 과거 구매 이력·상품 메타데이터로 다음 주에 살 상품 12개를 예측(MAP@12)
- 접근법: 여러 방식으로 후보 상품을 뽑는 1단계(candidate generation) + LightGBM Ranker로
  재정렬하는 2단계(re-ranking) 파이프라인
- 데이터: 2018-09-20 ~ 2020-09-22, 거래 3,178만 건, 고객 137만 명, 상품 10만 5천여 개

## 전체 스토리 흐름 (차트가 이 순서로 이어짐)

**1부. EDA — 데이터에서 가설을 세우고 검증** (h1~h11 파일들)
분석 초기에 "이럴 것이다"라는 가설 11개를 세우고 실제 데이터로 하나씩 검증. 채택된 가설은
바로 다음 단계(후보 생성 설계)에 반영됨.

**2부. 후보 생성 성능 비교** (candidate_source_comparison)
1부에서 나온 설계 방향대로 만든 6가지 후보 생성 방식 각각의 단독 성능.

**3부. 파이프라인 진행 경과** (pipeline_evolution_timeline)
규칙 기반 베이스라인부터 시작해서 여러 실험을 거치며 점수가 어떻게 변해왔는지 시간순 정리.
가장 중요한 포인트: backtest(자체 검증 점수)가 좋아져도 실제 리더보드 점수는 항상 따라오지
않았다는 것.

**4부. 오늘 만든 새 검증 방법론** (multiweek_eval_optuna_0906, seasonal_feature_saga)
"backtest 개선 ≠ 실제 성능 개선"이라는 3부의 문제를 풀기 위해 만든 다주(多週) 검증 기법과
그 검증 결과. 특히 seasonal_feature_saga는 이 다주 검증조차도 완벽하지 않다는 걸 보여주는
핵심 사례(교훈 차트).

**5부. 현재 모델 뜯어보기** (feature_importance_0906)
지금 실제로 쓰고 있는 모델이 어떤 특징(feature)을 가장 많이 참고하는지.

**6부. 종합 정리** (win_loss_summary)
지금까지의 모든 실험을 "성공/실패"로 나눠서 한눈에 정리.

## 이미지별 상세 설명

1. **h1_repeat_breakdown.png** — 가설 H1(자기 리피트 구매 성향) 검증. 전체 구매 이벤트 중
   같은 상품 재구매 14.1%, 같은 상품의 색만 다른 재구매 9.1%, 나머지 76.8%는 완전 신규 상품.
   → 결론: 예전에 산 것만으로는 추천 후보를 충분히 못 채운다.

2. **h2_category_affinity.png** — 가설 H2(카테고리 편향 구매) 검증. 특정 카테고리(남성복/
   아동복/여성복)를 3회 이상 산 고객이, 그 카테고리를 다시 살 확률이 전체 평균보다 몇 배
   높은지 비교(덤벨 차트: 연한 점=전체 평균, 진한 점=단골 고객). 남성복/아동복은 배수가
   크게(4.8배, 9.6배) 나와 강한 신호, 여성복은 원래 구매자가 너무 많아서(모집단 자체가
   64%) 배수가 약함(1.1배).

3. **h4_weekly_trend.png** — 가설 H4(계절성/트렌드) 검증. 2년치 주간 거래량 추이. 블랙프라이데이
   급증, 2020년 3~4월 COVID 락다운 시기 급감이 뚜렷하게 보임. → 트렌드 반영 특징량이
   필수라는 근거, COVID 구간은 예외적 시기로 따로 다뤄야 함.

4. **h5_h7_pricing_channel.png** — 가설 H5(개인 예산대 존재)와 H7(오프라인 vs 온라인 구매
   패턴 차이) 검증. 왼쪽: 개인별 가격 변동폭이 전체 평균보다 작다(=각자 정해진 예산대가
   있다). 오른쪽: 온라인 구매가 오프라인보다 평균 단가 +30%, 장바구니 총액 +108%, 구매
   개수 +60% 높다.

5. **h9_cold_start.png** — 가설 H9(콜드스타트 고객 비율) 검증. 학습 기간 동안 구매 0건/1건인
   고객이 전체의 10.3%로, 개인화 추천이 불가능한 "콜드스타트" 고객. → 이 고객들에게는
   개인화 모델 대신 인기 상품으로 대체 추천하는 설계 근거.

6. **h10_dead_stock.png** — 가설 H10(상품 수명주기) 검증. 카탈로그 상품 중 최근 12주간
   한 번도 안 팔린 상품이 60.8%. → 오래된/단종 상품은 인기 후보에서 걸러내야 함.

7. **h11_payday_effect.png** — 가설 H11(급여일 효과) 검증. 월중 날짜별 거래량을 지수화하면
   월말(22~29일)에 거래량이 확 높아짐(급여일 직후 소비 증가 패턴).

8. **candidate_source_comparison.png** — 1부의 결론을 반영해 실제로 구현한 6가지 후보
   생성 방식(자기 리피트/트렌드 인기/카테고리 유사/협업 필터링/아이템 공동구매/텍스트
   유사도) 각각의 단독 성능(Recall@12, MAP@12) 비교. 자기 리피트가 가장 강하지만 그래도
   전체를 커버하진 못해서, 6개를 다 합쳐야 상한선이 크게 올라감(점선 기준선).

9. **pipeline_evolution_timeline.png** — 가장 중요한 차트 중 하나. 프로젝트 시작(규칙 기반
   베이스라인)부터 지금까지 모든 주요 실험을 시간순으로 나열. 막대=실제 리더보드 점수,
   주황 점선=자체 검증(backtest) 점수. 빨간 글씨(X 불채택)는 backtest는 좋아졌지만 실제
   리더보드에서는 나빠져서 채택하지 않은 실험들. 검은 O는 현재 채택 중인 모델.

10. **multiweek_eval_optuna_0906.png** — "backtest가 좋아져도 실제 점수가 안 좋아지는" 문제를
    풀기 위해 오늘 새로 만든 검증법(여러 주로 재검증)의 첫 적용 결과. 과거에 backtest만
    보고 판단했던 두 가지 실험(하이퍼파라미터 튜닝, 최신 모델)을 재검증한 결과.

11. **seasonal_feature_saga.png** — 오늘의 핵심 사례. 계절성 관련 특징량을 새로 추가한 모델을
    테스트한 결과: 왼쪽 차트는 3개의 검증 주 모두에서 새 모델이 기존 모델을 앞섬. 오른쪽
    차트는 이 모델을 실제로 지표별(단일 검증 주/3주 평균/공개 리더보드/비공개 리더보드)로
    비교한 것인데, 앞의 3개 지표는 개선 또는 중립이었지만 마지막 비공개 리더보드에서는
    확실히 나빠짐(빨간 막대). → 다주 검증도 완벽한 안전장치는 아니라는 교훈.

12. **feature_importance_0906.png** — 지금 실제로 쓰고 있는 모델이 예측할 때 가장 많이
    참고하는 특징량 상위 15개 순위(막대가 길수록 중요). 최근 7일 판매량, 고객의 마지막
    구매 이후 경과일 등이 상위권.

13. **win_loss_summary.png** — 프로젝트 전체를 관통하는 요약. 지금까지 시도한 8개 주요
    실험을 직전 비교 기준 대비 얼마나 좋아지거나(파랑) 나빠졌는지(빨강), 공개/비공개
    리더보드 둘 다 기준으로 한 장에 정리. 초반 규칙 기반 → 2단 구성 전환이 압도적으로
    가장 큰 개선이었고, 그 이후는 대부분 작은 개선이거나 오히려 기각된 실험들.

## 요청

위 내용을 바탕으로, 13장의 이미지를 순서대로 보면서 PPT 슬라이드 대본을 갱신해줘.
